# Settings (database is authoritative)

Every XCrawler feature switch and operational limit is stored in the `settings` group of the `jooservices/laravel-config` database store and edited on **Cài đặt** (`/app#/settings`) or with `PUT /ui-admin/settings`. Defaults live in `config/javmeta_*.php` and do not read env. The only env values used by config files are enumerated in [`config/bootstrap_env_allowlist.php`](../../config/bootstrap_env_allowlist.php); `EnvironmentBootstrapAllowlistTest` fails if a config file reads any other key. That allowlist is for Laravel/framework and infrastructure bootstrap (database/cache/queue transports, external-service URLs or credentials, `APP_KEY`, `APP_URL`, and node identity); `JAVMETA_ALLOW_SAMPLE_SECRETS` is a CI-only switch for disposable integration credentials and is not enabled in deploy templates. The only direct `JAVMETA_*` config reads left are `JAVMETA_ALLOW_SAMPLE_SECRETS`, `JAVMETA_NODE_NAME`, `JAVMETA_NODE_ROLE`, `JAVMETA_ROLE`, and `JAVMETA_SENTRY_DSN`; all but the CI-only switch are host identity or Sentry bootstrap. All other legacy feature variables are mapped below for import only.

- **Registry and UI:** `config/javmeta_settings.php` defines each default config mapping, type, numeric range or JSON shape, Vietnamese label/description, group and application delay. Worker settings are grouped as Hàng đợi, Worker, Trình duyệt, Dọn dẹp and Thời gian chờ. JSON worker overrides accept known Horizon queue names and counts from 1–32; node overrides accept `main`, `worker`, or `role@hostname` with `default`, `direct`, `browser`, and per-queue maps.
- **Apply timing:** saved values apply at app boot, before each queue job, and before each console command. The settings page displays `áp dụng sau tối đa N giây`. `queue.feed_interval_seconds` accepts 5, 10, 15, 30 or 60 seconds; the scheduler polls it every 5 seconds, so changes apply without restarting the scheduler. Horizon worker changes are reconciled per node by `horizon:reconcile-workers`; the install wizard enables a systemd timer on main and worker nodes. Each master publishes the exact layout hash it booted with to Redis. Reconcile skips deploy locks, applies stable node jitter, serializes fleet restarts, records `workers_reconfigured`, and enforces at least a 10-minute per-node cooldown. Horizon's `fast_termination` remains off so jobs drain gracefully.
- **Migration:** first run `php artisan settings:import-env --dry-run`. It lists each missing setting, the current effective legacy env value or code default, and the source; secret values are always `[redacted]`. Then run `php artisan settings:import-env` to write the same values once. Existing saved settings are never overwritten, empty secrets are skipped, and partial writes are rolled back if an import fails. After the database values are verified, delete the registered legacy setting lines from each node's shared env: `JAVMETA_WORKERS_PER_QUEUE`, `JAVMETA_BROWSER_WORKERS_PER_QUEUE`, `JAVMETA_QUEUE_NAMES`, `JAVMETA_QUEUE_TIMEOUT`, `JAVMETA_QUEUE_TRIES`, `JAVMETA_QUEUE_MAX_TIME`, `JAVMETA_QUEUE_MAX_JOBS`, `JAVMETA_QUEUE_SLEEP`, `JAVMETA_QUEUE_STOP_GRACE`, `JAVMETA_QUEUE_DEPTH_LIMIT`, `JAVMETA_PER_SOURCE_INFLIGHT`, `JAVMETA_FEED_POOL_LIMIT`, `JAVMETA_PACING_HORIZON_SECONDS`, `JAVMETA_GAP_BLOCKED_MAX_SECONDS`, `JAVMETA_BLOCK_DELAYS`, `JAVMETA_FRESH_INTERVAL_MINUTES`, `JAVMETA_LOOP_PAUSE_SECONDS`, `JAVMETA_RECRAWL_*`, `JAVMETA_ALERT_*`, `JAVMETA_WATCHDOG_*`, `JAVMETA_READINESS_*`, `JAVMETA_BACKUP_*`, `JAVMETA_REPORT_*`, `JAVMETA_SEARCH_ENABLED`, `JAVMETA_EMBEDDER_ENABLED`, `JAVMETA_UI_LOGIN_REQUIRED`, `JAVMETA_OWNER_ADMIN_TOKEN`, `JAVMETA_MCP_API_KEY`, `JAVMETA_SENTRY_TRACES_SAMPLE_RATE`, `CRAWLERX_BROWSER_*`, `CRAWLERX_FLARESOLVERR_MAX_TIMEOUT_MS`, `CRAWLERX_FLARESOLVERR_URL`, `FLARESOLVERR_MAX_TIMEOUT_MS`, `FLARESOLVERR_URL`, `PLAYWRIGHT_URL`, `OPENOBSERVE_ENABLED`, `OPENOBSERVE_ORG`, `OPENOBSERVE_SERVICE_NAME`, `OPENOBSERVE_STREAM_LOGS`, `OPENOBSERVE_STREAM_METRICS`, `OPENOBSERVE_TIMEOUT`, `OPENOBSERVE_TRACE_SAMPLE_RATE`, `EMBEDDER_URL`, `EMBEDDER_DIM`, `ELASTICSEARCH_MOVIES_INDEX`, `ELASTICSEARCH_PERFORMERS_INDEX`, `NOTIFICATION_TELEGRAM_*`, and legacy `TELEGRAM_*`. Keep infrastructure bootstrap values, Sentry DSN and node identity in env.
- **Secrets and audit:** secrets such as Telegram credentials are encrypted at rest, write-only in the UI and redacted from `setting_changed`. Every successful edit emits the ops event `setting_changed` with the key, user and non-secret old/new value.
- **Validation and API:** invalid values return 422 per setting. Client deadlines must exceed their service deadlines: fetch worker timeout > fetch service timeout, Redis `retry_after` > worker timeout, browser gateway wait > Playwright/FlareSolverr service timeout, and gateway client timeout > gateway wait.

`GET /api/v1/config/browser-services` requires an API key with the `config` scope and returns the effective browser concurrency, queue sizes, timeouts, thresholds, retry values, cleanup ages, poll interval and `version`. It sends an ETag; clients poll every `poll_interval_seconds` (30 seconds by default) with `If-None-Match`, treat 304 as unchanged, and keep their last good response after network or server errors. The vm-tools cache refresher at `deploy/browser-services-config.mjs` writes JSON atomically, keeps its last good values, and creates safe defaults only before the first good response. Provide `JAVMETA_CONFIG_API_URL`, `JAVMETA_CONFIG_API_KEY` (a key with the `config` scope), and optionally `JAVMETA_CONFIG_CACHE_FILE` to its systemd environment. The remote browser gateway must poll this endpoint and apply the same contract; its implementation lives outside this repository and must be updated alongside deployment.

New features (Telegram follow notifications and bot, the library scanner) read their configuration only from here.

## Performance warming

`perf.warm_enabled` (default `true`, group Tìm kiếm) controls the scheduled `perf:warm` command. It appears automatically on Cài đặt and is applied from the database to `javmeta_perf.warm_enabled`. Turning it off stops proactive refreshes; request-driven caches still work. No environment variable is needed. See [performance](performance.md) for TTLs, subminute scheduling and verification limits.

## Hybrid search HTTP budget

`search.budget_ms` (default 300, range 25–1500, group Tìm kiếm) maps to `javmeta_search.budget_ms` through the database settings service. It limits optional HTTP work within one hybrid search. SQL and response serialization can exceed that budget. A timeout falls back to keyword results; the existing response keys remain unchanged. No environment variable is needed. See [performance](performance.md) for measurements and acceptance limits.

Media processing settings (`media.*`) are defined in `config/javmeta_media.php` and registered in `config/javmeta_settings.php`. They are database/UI settings, never environment variables. See [media.md](media.md) for queue limits and bootstrap credentials.

Stream capture settings (`capture.*`) default in `config/javmeta_capture.php`. Capture is off until the owner enables it on the Settings page; duration, output size, manifest count/size and HTTP timeout limits are editable there. Enabling capture never disables the DRM/content policy checks.

## Outbound base URLs and Telegram groups

All service URL settings (`media.api_url`, `search.embedder_url`, `ai.ollama_url`, `downloads.qbittorrent_url`, `telegram.api_base`) require a host and an HTTP(S) scheme. Telegram requires HTTPS; HTTP is allowed only for the exact hosts `localhost` and `127.0.0.1` for local tests. Base URLs reject userinfo, query strings and fragments, including empty `?` or `#`. Empty URLs may disable optional integrations. Keep credentials in their dedicated secret fields. Private network qBittorrent addresses remain supported.

A previously saved invalid URL is ignored during application boot and direct settings reads. A valid config default applies (otherwise the address stays empty), and the Settings page displays a warning without returning the unsafe value; save a valid address to clear it. URL credentials, queries and fragments are stripped from `setting_changed` events and URL text in local/remote logs.

`telegram.owner_user_id` is a positive integer, empty by default. For group/supergroup chats both `telegram.chat_id` and the sender's user ID must match; an unset owner refuses all group commands and download callbacks. Callback authorization uses `callback_query.from.id`, not the sender of the bot's original message. Private chats retain chat-ID authorization and do not require this setting.

`observability.fetch_attempts_retention_days` defaults to 14 in
`config/javmeta_observability.php` and maps to
`javmeta_observability.fetch_attempts_retention_days`. The daily
`crawler:prune-fetch-attempts` command applies the current database value.
See [fetch diagnostics](telemetry.md#fetch-attempts).

Crawl lanes are controlled by `crawl.lanes_enabled`, `crawl.lane_browser_percent`, `crawl.lane_min_attempts`, `crawl.lane_direct_pins`, `crawl.lane_browser_pins` and `queue.browser_depth_limit`. See [queue.md](queue.md) for classification, precedence and fleet rollout. Horizon worker counts are read from the database at boot and reconciled automatically by each node.
